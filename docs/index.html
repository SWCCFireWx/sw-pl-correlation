Southwest Preparedness Level: what moves with it, and what moves first?

Every FEMS daily value from every RAWS station in the Southwest GACC, plus fire starts and acres, compared with the Southwest Area PL. The page answers three questions: which values track PL, which ones change before PL changes, and is there a value we aren't watching that does as well as ERC?

1. Bottom line

Written from the data each time it updates. "Match" is a correlation score from 0 (no relationship) to 1 (moves in lockstep).

2. Every value, ranked by how well it matches PL

Each value's best match across all lead times. Same-day compares today's value with today's PL. Best lead is how many days ahead it matches PL best. A leads PL tag means the value matches future PL better than today's PL, so it moves first. The Pre-monsoon and Monsoon columns show the same value's best match in each half of the season (split date set above), so you can see values that only matter in one half. Click a row to load it into the charts below.

3. Lead-time table: does the value move before PL?

Rows are values (top 25). Columns compare today's value with PL that many days later. Darker blue means a stronger match where the value rises with PL; darker red means a stronger match where it falls as PL rises (fuel moistures, humidity). If a row gets darker to the right, that value is an early warning.

4. Coordinate plane: the value (x) against PL (y)

Each dot is one day. PL dots are spread up and down slightly so they don't stack on one line. The line is the straight-line trend. Squares mark the typical (median) value at each PL. A clear upward slope with tight groups means a useful predictor; a flat cloud means none. Switch y-axis to plot any two values against each other, colored by PL.

5. Typical value at each PL

The bar spans the middle half of days (25th–75th percentile); the line runs 10th–90th; the dot is the median. If the bars climb steadily with little overlap, the value separates PLs well. Where one PL's bar starts is a candidate breakpoint.

6. What it does before PL goes up

Averaged over every PL increase. Day 0 is the day PL rose. The value is shown as distance from that month's normal (0 = normal, +1 = one standard deviation above normal). A curve already climbing at days −14 to −7 is a usable early signal.

7. Through the season

PL (top) and the chosen value (bottom) share the same dates, so you can see which turns first. Separate panels rather than two y-axes, so neither scale is distorted.

How this works and its limits

Data
  • PL: Southwest Area PL from the provided history sheet (2004 onward), with today's level read from the SWCC Fire Environment Report. Feb 29 is missing from the sheet, so leap days are filled from Feb 28 and Mar 1 (same value if they match, otherwise the average rounded up). Filled days are marked leap_fill in sw_pl.csv.
  • FEMS: daily NFDRS summary and daily weather summary from the FEMS public API for . Stations are every RAWS in Arizona and New Mexico that falls inside a current Southwest GACC Predictive Service Area (PSA), using the national PSA boundary layer. Texas and Oklahoma are not included, and Grand Canyon NP (Great Basin GACC) is excluded using the NPS park boundary, for both stations and fire starts. The list is refreshed weekly, and the update log names every station left out. Each value is the median across reporting stations that day. The "% of stations in their highest/driest 10%" values count how many stations are at an extreme for their own history, a measure of how widespread the danger is. Station list and update log.
  • Fires: wildfire starts with point of origin in Arizona or New Mexico, from the national WFIGS/IRWIN incident service, counted by discovery date (Arizona time). State is used rather than the record's GACC tag, because older records carry the old GACC boundary. "Acres" is each fire's final size, credited to the day it started.
  • PSA ERC(Y) / BI: key-station averages per PSA, using the method, station list and percentile breakpoints in the breakpoints workbook (raw/breakpoints.xlsx). The Southwest values are the average PSA percentile and the number of PSAs at or above the 90th/97th.
  • Lightning: NOAA NCEI daily cloud-to-ground flash counts (NLDN, 0.1° tiles) summed per PSA. NOAA posts it monthly, so the latest weeks are blank, not zero.
  • Acres burned per day: the change in Southwest year-to-date acres in NICC's daily situation report (IMSR). Weekly reports are spread evenly over the week.
  • Area picker: each PSA uses only its own stations, key-station ERC(Y)/BI, fire starts and lightning, compared with the Southwest PL.
  • Updates: a GitHub Action runs every 15 minutes. It backfills a few station-years per run back to , then keeps the current year fresh.
Statistics, in plain terms
  • Match is Spearman rank correlation. It suits PL because PL is a ranking (1–5), not a measurement. 0.6+ is strong, 0.4–0.6 moderate, 0.2–0.4 weak, below 0.2 essentially none.
  • Lead: today's value vs. PL N days later. Because PL changes slowly, nearby lead times always score similarly. Look for a clear improvement, not tiny differences.
  • Mar–Oct (default) is the whole Southwest fire year. Pre-monsoon runs from Mar 1 to the split date; Monsoon runs from the split date to Oct 31. The split can be set to Jul 1, 8 or 15. The two halves often behave differently: dry fuels and wind drive the pre-monsoon season, while lightning and rain drive the monsoon. A value can matter in one and not the other. Full year includes winter, when PL sits at 1, which makes anything seasonal look correlated.
  • "Change over 7 days" versions test whether a fast rise matters more than the level. "7-day total" smooths noisy daily fire counts.
  • Correlation is not cause. PL is a human decision that also weighs resource drawdown, national PL, and fires elsewhere, which no weather value captures.
Known gaps
  • "Acres of fires started that day" credits each fire's final size to its start day; "Acres burned per day (IMSR)" is the day-by-day growth.
  • Stations have different record lengths. The median uses whoever reported that day, and the "Stations reporting" value is in the downloads.
